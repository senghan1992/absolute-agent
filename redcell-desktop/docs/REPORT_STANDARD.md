# RedCell 진단 리포트 표준

대상 URL 하나를 넣고 나온 리포트를 **시니어 보안팀 팀장이 직접 올린 수준**으로
맞추기 위한 규칙. 코드가 바뀌면 이 문서도 같이 고친다 — 규칙의 근거 위치는
각 항목 끝의 `(코드)` 에 적어 두었다.

---

## 1. 위험도 등급 (A~F)

**평균으로 등급을 내지 않는다.** 심각도(영향)와 검증(확신)은 서로 다른 축이고,
평균을 취하면 "직접 확인된 치명 1건"이 "추측으로만 나온 낮은 등급 5건"에
묻혀 **'안전' 으로 표시되는 사고**가 난다. 그래서 등급은 **규칙 기반 하한(floor)** 으로
정한다 — 확인된 고위험 발견은 다른 항목의 수·추측성과 무관하게 등급을 끌어올린다.

| 등급 | 라벨 | 조건 (위에서부터 첫 충족) |
|---|---|---|
| **F** | 심각 | `치명` + `[실증]` (직접 확인된 치명) |
| **D** | 위험 | `치명` + `[가정]` · 또는 `높음` + `[실증]` |
| **C** | 보통 | `높음` + `[가정]` · 또는 `중간` + `[실증]` |
| **B** | 양호 | `중간` + `[가정]` · 또는 `낮음` + `[실증]` · 또는 `낮음` + `[가정]` |
| **A** | 이상 없음 | **발견 0건** (확인된 결함이 하나도 없을 때만) |

- **A 는 '발견 0건' 만 뜻한다.** 발견이 1건이라도 있으면 최소 **B(양호)** 다 —
  `낮음` + `[가정]` 만으로 A 로 내려가지 않는다. 이전 규칙에서는 그 조합이 A 로
  표시되면서 화면에 "A 안전" 과 "3개 발견" 이 동시에 떠 혼선을 만들었다.
  확인하지 못한 것이 "확인되지 않은 것" 은 아니기 때문이다.
- 등급 라벨은 다섯 가지로 고정한다 — A 이상 없음 / B 양호 / C 보통 / D 위험 / F 심각.
  '안전' 라벨은 쓰지 않는다(발견이 있어도 안전하지 않다는 뜻으로 오독된다).
- 등급 표시는 **가장 위험한 루트 1건**을 근거로 한다(심각도 → 검증 순).
- 요약 헤더에는 등급과 함께 **판정 근거 한 줄**과 **최고 위험 루트 이름**을 노출한다.
  근거 없는 등급은 리포트 요약에서 가장 위험한 사고다.
- 코드: `ui/app.js` `gradeOf()` / `reportStats()`, 회귀 테스트 `ui/tests/grade.test.mjs`

### 위험지수 (0~10)

`max(심각도 지수 × 확신 계수)` — 평균이 아니라 **가장 위험한 루트가 결정한다**.

| 심각도 | 지수 | 확신 | 계수 |
|---|---|---|---|
| 치명 | 10 | 실증 | 1.00 |
| 높음 | 7.5 | 징후 | 0.85 |
| 중간 | 5 | 가정 | 0.70 |
| 낮음 | 2.5 | | |

코드: `ui/app.js` `SEV_INDEX` / `VER_FACTOR`

## 2. 검증 상태 — 실증 / 징후 / 가정

| 상태 | 뜻 | 판정 근거 |
|---|---|---|
| `[실증]` | 직접 확인됨 | P0 증거([P-###]) + P1 재확인(`verify-*`) 또는 하네스가 직접 재요청해 응답을 확인 |
| `[징후]` | 일부만 확인 | 오류 노출·헤더·설정 파일 등 정황은 있으나 재현 실패 |
| `[가정]` | 추론 | 설명 기반 추론 — 실측 불가 사유를 반드시 명시 |

- **셋 중 하나만** 쓴다. 루트 하나에 둘을 섞지 않는다.
- `[실증]` 이 아니면 **위험도를 한 단계 낮춰** 표기한다(치명 가정 → 높음).
  엔진의 `verdict`(confirmed/signal)·`category` 매핑과 같은 원칙이다.
- **기계 대조**(`verify_report_claims`)가 [실증] 주장을 재요청한다. 하나라도
  후보 URL에서 증거가 재현되면 확인을 유지하고, 어디에서도 재현되지 않으면
  [징후] 로 강등된다. 존재하지 않는 `[P-###]` 인용은 환각으로 판정되어 삭제된다.
  코드: `src-tauri/src/main.rs` `verify_report_claims()`, `src-tauri/src/deep_instr.rs` `extract_evidence_claims()`

### 2-1. 심각도 대조 (위험도 과대평가 감사)

리포트의 위험도 **주장**을 그 루트가 인용한 P0 근거의 **최대 심각도**와
기계 대조한다. 도구 스스로가 자기 리포트를 감사하는 장치다.

| 판정 | 조건 | 취급 |
|---|---|---|
| `심각도 과대` | 주장 등급 > 인용 근거의 최대 등급 | **반드시 낮춰 적는다** (병합 규칙 9) |
| `심각도 과소` | 주장 등급 < 인용 근거의 최대 등급 | 위험 은폐 — 올려 적는다 |
| `심각도 근거없음` | 유효 `[P-###]` 인용 0건 | 정보성(위반 아님 — 웹 실측 시나리오가 여기에 해당) |

- 등급 랭크: 치명 4 · 높음 3 · 중간 2 · 낮음 1 / 엔진 `critical` 4 · `high` 3 ·
  `medium` 2 · `low` 1 · `info` 0.
- 존재하지 않는 P-ID 인용은 무시한다(환각 처리는 별도). 근거 최대값은
  **섹션(루트) 단위**다 — 같은 루트 안의 개별 인용별 차이는 구분하지 않는다.
- 결과는 병합 프롬프트의 `### 심각도 대조` 절로 들어가며, 과대 강등은
  「불일치 [실증] → [징후] 강등」과 같은 강제력을 갖는다.
- 코드: `src-tauri/src/main.rs` `audit_claim_severities()`,
  `src-tauri/src/deep_instr.rs` `extract_root_claims()`

### 단일 턴 경로의 검증 한계 (자동 수정 없음)

채팅으로 지시한 **단일 턴 진단**도 같은 표준(리포트 형식 · P0 증거 · 결과 탭의
`report: "final"`)을 따르지만, 심층 경로와 달리 **병합 단계가 없다.** 그래서 기계 대조
결과는 **노트로만 알리고 자동 수정은 하지 않는다** — 재현되지 않은 [실증] 주장을
[징후] 로 강등시키거나 환각 `[P-###]` 인용을 지우지 않는다. 원문은 그대로 두고
대조 결과(확인·불일치·미시도 건수와 환각 P-ID)만 정직하게 노출해 사람이 확인·
수정할 수 있게 한다. 심층 경로의 병합 단계가 하는 자동 보정은 이 경로에 없다.
코드: `src-tauri/src/main.rs` `finalize_single_turn_report()`

## 3. 객관 지표 — CVSS · CWE · OWASP

- P0 스윕이 각 증거에 붙이는 **CVSS 3.1 벡터·기본 점수·CWE**를 리포트는
  **그대로 인용**한다. LLM 이 재계산하거나 임의로 바꾸지 않는다.
- 매핑이 없는 카테고리(정찰 메모·정보 항목)는 **점수가 없다** — 지어내지 않고
  `CVSS: -` 로 적는다.
- 위험도는 CVSS 3.1 기준 대략치와 정합해야 한다
  (치명 9.0~10.0 / 높음 7.0~8.9 / 중간 4.0~6.9 / 낮음 0.1~3.9).
  단, **검증 상태가 낮으면 그만큼 낮게** 적는다.
- 코드: `src-tauri/src/probes.rs` `category_scoring()` / `hit_scoring_note()` / `category_cwe()`

## 4. 리포트 구조

```
# <서비스명> 진단 리포트
## 0. 한눈에 보기        — 3줄 요약 + 요약 표(루트·위험도·CVSS·검증·공격 방법·탈취 정보·보완 요약)
## 1. 진단 범위 및 가정   — 기술 스택(P0 탐지값 우선)·경계·미점검 영역
## 2. 공격 표면           — 인증/입력/데이터 흐름/외부 연동/배포/비즈니스 로직
## 3. 위험도 판정 기준     — CVSS 3.1 루브릭(위 표)
## 4. 공격 시나리오       — 루트별 고정 형식(아래)
## 5. 개선·보완 권고      — 우선순위·문제·영향·CVSS·보완 코드·검증 방법·노력·완료 기준
## 6. 실측 확인           — P0 요약·[P-###] 대응·재현 시도 결과
## 7. 확인된 보안 통제    — 잘 되어 있는 것(근거 1줄)
## 8. 한계와 미검증 영역  — 커버리지 원장 out_of_scope·blocked·deferred 그대로
부록 A. 재현 절차        — 루트별 curl 1줄
부록 B. 참고 기준        — CWE·OWASP Top 10 (2021)·NIST SP 800-115
```

### 루트 고정 형식

`### 루트 N. <이름> [위험도]` 아래에 아래 라벨 줄을 **순서대로** 쓴다.
UI 가 라벨 줄을 인식해 필드·플로우·플레이어로 렌더한다.

```
위험도: 치명|높음|중간|낮음
CVSS: 9.8 (CVSS:3.1/AV:N/AC:L/PR:N/UI:N/S:U/C:H/I:H/A:H) · CWE-89 · OWASP A03:2021
진입점: …
공격 흐름: 공격자 → 진입점 → (취약점) → 중간 결과 → (탈취) → 최종 피해
탈취 정보: …
공격 방법: …
재현: curl -sS 'https://…' …
멘토 노트: …
증거: 실제 응답·헤더·본문 발췌 1~3줄
영향: …
시뮬레이션: 1. 행동 → 결과
검증: [실증|징후|가정] 근거
보완: 복붙 가능한 코드·설정
```

- 같은 근본 원인(같은 진입점·같은 결함)의 발견은 **하나로 합친다** — 개수로 위험을
  부풀리지 않는다.
- 코드: `src-tauri/src/deep_instr.rs` `REPORT_SPEC`

### 결과 탭 카드 구조 (UI)

리포트 본문은 `## ` 절 경계마다 **한 장의 카드**가 된다. 이 앱의 사용자는 보안
전문가가 아니므로 "지금 뭘 해야 하지?" 를 맨 위에서 바로 볼 수 있어야 한다.

| 카드 | 본문 절 | 배지 | 순서 |
|---|---|---|---|
| 요약·범위 | 루트 앞(0~4절) | `요약·범위` | 1 |
| 해야 할 일 | `## 5. 개선·보완 권고` | `해야 할 일` | 2 — **루트보다 앞** |
| 발견 | `### 루트 N. …` | `발견` | 3 |
| 직접 확인 | `## 6. 실측 확인` | `직접 확인` | 4 |
| 잘 되고 있는 | `## 7. 확인된 보안 통제` | `잘 되고 있는` | 5 |
| 한계 | `## 8. 한계와 미검증 영역` | `한계` | 6 |
| 부록 | `부록 A/B` | `부록` | 7 |

- 절 제목은 **번호·공백·괄호·앞뒤 표현 차이를 허용**한다 —
  `5. 개선·보완 권고 (우선순위)` 와 `한계와 미검증 영역` 이 같은 종류로 잡히게.
  판별은 소문자·공백 제거 후 핵심 키워드(권고·실측·통제·한계·부록) 기준이다.
  어떤 절도 해당하지 않으면 '기타' 카드 한 장으로 합친다(내용 유실 금지).
- 요약 카드(맨 위)는 접힘 상태에서도 **등급 · 위험지수 · 등급 근거 · 발견 분포 ·
  '이 리포트를 얼마나 믿어야 하나' · '지금 해야 할 일'** 이 항상 보인다.
  서랍(접힘)에는 필터 · 바로가기 · 범례만 둔다.
- '지금 해야 할 일' 은 권고 절의 `[P0]`/`[P1]` 항목에서 뽑는다(최대 3건).
  항목이 없으면 루트의 `보완:` 필드로 대체하고, 그것도 없으면 조용히 숨긴다.
  각 항목 클릭 → 해당 발견 카드로 이동 + 잠깐 강조.
- CVSS 한 줄은 **위험 점수**(점수 + 벡터)와 **분류**(CWE · OWASP) 두 필드로 나눠
  보여준다. CWE/OWASP 번호에는 한국어 툴팁(한 줄 설명)이 붙는다.
- 우선순위 배지 색은 4단계 — P0 빨강 · P1 주황 · P2 노랑 · P3 회색.
- 코드: `ui/app.js` `segmentDiag()` / `renderReportSummary()` / `parseActionItems()`

## 5. 한계와 미검증 영역 (추측 금지)

P0 스윕은 **점검 커버리지 원장**(공격 클래스 × 표면)을 남긴다. 각 단위의 상태:

| disposition | 뜻 | 리포트 처리 |
|---|---|---|
| `covered` | 검사했고 발견 없음 | 통과로 보고 |
| `finding` | 검사했고 발견 있음 | 해당 루트로 |
| `deferred` | 예산·취소로 미검사 | **한계 섹션에 명시** |
| `out_of_scope` | 옵션 미지정·미동의 | **한계 섹션에 명시** |
| `blocked` | 환경·연결 실패 | **한계 섹션에 명시** |

### TLS 계층 검사 범위

`tls-cert` 단위가 담는 것(베이스):
- 인증서 만료(임박) — DER/X.509 최소 파서로 notBefore/notAfter 판독
- 협상된 TLS 버전(TLS 1.2 미만이면 high), 약한 암호군(medium)
- 검증 루트 기준 판정: 만료 / 호스트명 불일치 / 알 수 없는 발급자(자체 서명 포함)

담지 **않는** 것(한계로 적을 것): 인증서 경로·서명 검증, 키 길이, HPKP·CT,
인증서 갱신 주기 자동 확인, 클라이언트 측 TLS 설정.

### 그 밖의 최근 보강 단위

| 단위 | 담는 것 | 등급 |
|---|---|---|
| `cache-store` | 로그인 폼·인증 API 응답의 `Cache-Control: no-store/private` 누락 (CWE-525) | medium |
| `sri` | 외부 CDN 스크립트의 `integrity` 속성 누락 (CWE-494) | low |
| `session-invalidation` | 로그아웃 후 **동일 쿠키**가 여전히 유효한지 (CWE-613) — **동의 기반에서만** | high |
| `cors` | preflight `Access-Control-Max-Age` 과다 + `*` Origin·자격증명 동시 노출 | medium/high |
| `paths` | WSDL·SOAP 엔드포인트와 백업 확장자 변형(.bkp/.tar/.7z/.dump 등) 추가 | Info~ |

- 미검사 항목을 "점검 완료"로 쓰지 않는다. 한계 섹션은 **무엇을 · 왜 · 다음 단계**를
  적는다(근거: `needs_validation` 인계 항목).
- 코드: `src-tauri/src/probes.rs` `build_coverage()` / `coverage_digest()` / `needs_validation_from_hits()`

## 6. 표지 (내보내기·복사본)

저장·복사되는 리포트 맨 위에 다음이 붙는다 — 파일이 스스로를 설명해야 한다.

```
> **RedCell 보안 진단 리포트**
```
