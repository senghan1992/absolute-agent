# RedCell Audit

## runAssault(방어자 시점)

- **무엇을 변경했는가**: `src/assault/noise.ts` 는 실행 내내 `NoiseLedger` 가
  (1) 대상에 보낸 총 요청 수 (2) 401/403 (부정권한) (3) 429 (속도제한) (4) 5xx
  (서버오류) (5) 상위 5개 경로 (6) 응답 시그니처(서버 지문 해시) 를 누적하고,
  `pipeline.ts` 가 이를 `Report.noise`(`NoiseSummary`)로 리포트 JSON 에 붙인다.
  `format.ts` 는 리포트.md/html 에 "방어자 시점 — 이번 실행에서 대상이 받은 흔적"
  섹션을 출력한다. `cli.ts` 는 완료 시 한 줄 요약을 낸다. `README.md` 는
  "블루팀/SOC 인계용이며 탐지 회피 기능이 아님"을 명시한다.
- **왜 변경했는가**: 공격 실행은 대상 방화벽/WAF 로그에 남은 흔적으로 추정
  (즉각적 차단) 여부가 결정적이며, 그 추정의 수치를 제공하기 위한 최소 인계 자료다.
  스모글링·파이프라이닝 등 1개의 로직상 페이로드가 물리적으로 여러 번의 요청으로
  확장되는 경우 대상 로그가 더 많이 남는다는 점도 함께 기재했다.
- **어떤 데이터가 추가되는가**: `report.json` 에 `noise` 키 1개(정수 4개 + 문자열
  배열 2개). 샘플 1건도, 사용자 데이터도 마스킹 대상이 아니다(이 섹션에는 대상
  경로와 요청 수만 들어가고 페이로드/크레덴셜은 포함하지 않는다). 기존 필드 구조
  `report.md/html` 에 섹션 1개 추가, JSON 스키마는 `noise` 키만 추가(기존 필드
  무변경).
- **무엇을 검증했는가**: `test/assault/noise-e2e.test.ts` 2건(신규) — (a) 실제
  로컬 취약 서버에 runAssault를 돌렸을 때 리포트의 `noise.requests` 가 대상이
  받은 물리 요청 수와 정확히 일치(누락 없음), (b) 같은 대상·옵션으로 2회 실행하면
  `noise`(requests/statuses/topPaths) 가 동일(결정적 재현). 기존 477개 테스트는
  476 통과 + autopilot.test.ts 1건이 비결정적(flaky, 단독 3회 중 2회 통과)으로
  확인. flake 는 본 변경과 무관(동일 파일은 실행 간 결과 변동). `tsc --noEmit`
  클린.
- **위험**: 미발생. 본 섹션은 대상 데이터(요청 수, 경로) 만을 출력하고 페이로드
  ·크레덴셜 등 민감 데이터를 출력하지 않는다.
